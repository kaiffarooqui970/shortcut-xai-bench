# Findings log

Observations made while building the benchmark, in the order they were made.
Each entry says where its evidence lives. The README's findings section is
written from this log plus the final sweep; nothing here is dropped silently.

## 1. subtle and subtle_checker are equally learnable (2026-09-24)
At rate 1.0 (ResNet-18 width 64, 4 epochs, corner position), the uniform +15
blue shift and the 2x2 checkerboard of the same peak amplitude gave the same
reliance gap: +0.534 vs +0.532, with trigger flip rates of 18% vs 21%. The
expected high-frequency advantage of the checkerboard did not show up.
`subtle_checker` stays in the code but is not swept, because a uniform channel
shift is the more realistic artifact (lighting or sensor).
Evidence: `results/precheck/initial_cnn_w64_4ep.md`.

## 2. The ViT relies on the shortcut more than the CNN, despite lower accuracy (2026-09-24, single seed)
Subtle patch, rate 1.0, seed 0, corner position: ViT gap +0.67 vs CNN +0.48,
trigger flip rate 36% vs 16%, while ViT validation accuracy is 72% vs 86%.
Obvious patch: both models saturate (gap about 1.0). HYPOTHESIS until the sweep
tests it across rates and seeds; `results/reliance_by_model.md` will hold the
test. If it holds, it is a finding, not a footnote.
The ordering held at every position tried (subtle, rate 1.0, seed 0):
| position | ViT gap | CNN gap | ViT flip | CNN flip |
|---|---|---|---|---|
| flush corner | +0.67 | +0.48 | 36% | 16% |
| (22, 22), superseded | +0.85 | +0.73 | 64% | 26% |
| **corner, inset 1 (final)** | **+0.86** | **+0.66** | **66%** | **23%** |
Obvious patch: both gaps saturate at about 1.0 (a tie), but the flip rate still
differs: ViT 100% vs CNN 79%.
Evidence: `results/precheck/learnability.md`, `results/archive/learnability_*.md`,
`results/reliance_by_model.md` (regenerated by the sweep at every rate and seed).

## 3. captum's LRP diverges on the ViT (2026-09-24)
captum has no transformer rules. Epsilon-LRP relevance on the ViT summed to
about 1e13 to 1e16 for a logit of about 0.3. It was replaced with CP-LRP
(Ali et al. 2022): attention, LayerNorm scale and GELU gate are frozen, so
LRP-0 equals gradient x input. Unit test: relevance sums exactly to the logit
once additive terms are removed.
Evidence: `tests/test_attribution.py::test_vit_lrp_mode_keeps_forward_and_conserves_relevance`.

## 4. Grid alignment would have favoured grid-based methods (2026-09-24)
With the patch flush in the bottom-right corner, every patch edge lay on the
4 px KernelSHAP superpixel grid, the 8 px CNN Grad-CAM grid (layer4, 4x4 map)
and the 4 px ViT patch grid. So KernelSHAP and Grad-CAM could isolate the patch
by construction.
- First fix, superseded: origin (22, 22), with every edge 2 px off the 4-grid.
  This moved the patch onto the object more often (content proxy for the
  obvious patch: 14.7% vs 9.2% in the corner, tau = 24). A method that points
  at the object would then score as "found the shortcut".
- Final: bottom-right corner, inset 1 px. Edges are at 27, 31 (obvious) and
  23, 31 (subtle); mod 4 = 3, and mod 8 = 3 or 7, so no edge lies on any grid
  line. This is the smallest move that achieves that. Content overlap is back
  to corner level (8.0%).
Evidence: `tests/test_grid_alignment.py` (fails at inset 0), `results/patch_content_proxy.md`.

## 5. Some Grad-CAM heatmaps are all zero on the ViT (2026-09-24)
2 of 100 ViT Grad-CAM maps were exactly zero after the ReLU (subtle, rate 1.0).
The scoring treats a flat map as chance level (AUC 0.5; pointing = mask
fraction since #8's fix, previously a miss).

## 6. Patch position changes how strongly the shortcut is learned (2026-09-24, single seed)
Subtle patch at rate 1.0: the reliance gap was +0.48 (CNN) and +0.67 (ViT) with
the patch flush in the corner, but +0.73 (CNN) and +0.85 (ViT) at (22, 22),
further inside the image. The obvious patch saturated (gap about 1.0) at both
positions. Shortcut strength is not a function of the injection rate alone, so
results from one position may not transfer to another. The ViT > CNN ordering
held at both positions.
Evidence: `results/archive/learnability_corner_position.md`, `results/archive/learnability_origin22.md`.

## 7. Scoring choices a reviewer will ask about (2026-10-13)
Recorded here and in the `src/shortcutbench/scoring.py` docstring.
- **k for top-k = the mask's pixel count** (`scoring.top_k: mask`): 16 px for
  the obvious patch, 64 px for the subtle one. With this k a perfect heatmap
  scores P = R = 1, and P == R by construction, so precision and recall are one
  number here; they would separate only under a fractional k.
  *Update 2026-10-13:* results now carry a single `topk` column instead of two
  identical ones. **`topk` values are not comparable across patch types**: k
  (16 vs 64), the mask and chance level (1.6% vs 6.3%) all differ; compare
  methods within a patch type, or against the random baseline. A secondary
  fixed-k view (k = 64 for both: `precision_k64`, `recall_k64`) is computed
  from the cached heatmaps. It removes the k difference but not the mask-size
  difference (obvious precision_k64 is capped at 16/64 = 0.25), so it is
  secondary, not a fix.
- **The pointing game is stricter than the standard argmax definition.** A hit
  requires EVERY pixel tied at the maximum to be inside the mask; argmax would
  pick the first tied pixel in memory order (top-left first), which is
  arbitrary and position-biased. Measured consequence: see #8.
- **Channel reduction happens before scoring.** Heatmap files are already
  (N, 32, 32) float32; scoring never sees channels. Rule, per method
  (`src/shortcutbench/attribution.py`):
  | method | reduction |
  |---|---|
  | integrated_gradients, lrp, guided_backprop | `_reduce`: sum over RGB of \|attribution\| (absolute, then sum) |
  | kernel_shap | identical across channels by construction; channel 0, then clamp_min(0) (positive evidence only) |
  | gradcam | no channels; ReLU on the CAM (positive only), bilinear upsampling to 32x32 |
  | random | iid uniform, already 2-D |
  So pixel methods count evidence AGAINST airplane as salient, while
  KernelSHAP and Grad-CAM drop it. Changing this requires recomputing every
  heatmap. (The cache key now includes the rule: see #9. Sensitivity of the
  rankings to this rule: see #11.)

## 8. Strict pointing scores Grad-CAM and KernelSHAP as 0 for reasons unrelated to the explanation (2026-10-13)
On obvious r0.9 cnn s0 (first run trained by the full sweep), KernelSHAP had
16 pixels tied at the max on 100/100 images and Grad-CAM on 69/100; IG, LRP,
Guided Backprop and random had exactly 1 on every image. The plateau is
rows/cols 28-31 in 99 (KernelSHAP) and 69 (Grad-CAM) images; the mask is
rows/cols 27-30. Only 9 of the 16 plateau pixels are in the mask, so the strict
rule scores a miss although the maximum sits on the patch.
- KernelSHAP: its 4 px superpixels make plateaus by construction.
- Grad-CAM is upsampled BILINEARLY, not nearest-neighbour, but with
  align_corners=False every pixel beyond the outermost cell centre is clamped
  to the edge value, so the corner 4x4 block of a 4x4 CAM is exactly constant.
- The 1 px inset (#4) that keeps patch edges off every grid is what places the
  plateau half on, half off the mask.
Pointing on this run: Grad-CAM 0.000 and KernelSHAP 0.000, though their AUCs
are 0.982 and 0.956. Sweep-wide (valid runs), obvious patch: pointing 0.000 for
both, AUC 0.795 / 0.840. Their pointing scores therefore measure plateau
geometry, not localisation, and must not be read as "fails to find the
shortcut". Not yet changed; candidate fixes: credit the fraction of tied-max
pixels inside the mask (expected value under random tie-breaking, consistent
with top-k), or report pointing only for methods without plateaus.
Evidence: tie counts in the 2026-10-13 session; `results/results.csv`.

**Resolved (2026-10-13): fractional credit.** `pointing_game` now returns the
share of tied-max pixels inside the mask, the expected hit rate under uniform
random tie-breaking, which is the same convention as top-k. A flat map now
scores the mask fraction (chance) instead of 0. Scores only, no retraining:
AUC and top-k are bit-identical, and no pointing score went down. Mean over
valid runs and all rates, old (strict) → new (fractional):
| method | obvious cnn | obvious vit | subtle cnn | subtle vit |
|---|---|---|---|---|
| Integrated Gradients | 0.363 → 0.363 | 0.932 → 0.932 | 0.396 → 0.396 | 0.653 → 0.653 |
| Grad-CAM | 0.000 → **0.398** | 0.000 → **0.041** | 0.000 → **0.068** | 0.019 → **0.065** |
| LRP | 1.000 → 1.000 | 0.938 → 0.938 | 0.414 → 0.414 | 0.598 → 0.598 |
| KernelSHAP | 0.000 → **0.541** | 0.000 → **0.348** | 0.060 → **0.191** | 0.005 → **0.343** |
| Guided Backprop | 0.999 → 0.999 | 0.172 → 0.172 | 0.309 → 0.309 | 0.589 → 0.589 |
| random | 0.013 → 0.013 | 0.013 → 0.013 | 0.042 → 0.042 | 0.043 → 0.043 |
Only Grad-CAM and KernelSHAP change. IG, LRP, Guided Backprop and random
have a unique maximum on every image, so their scores cannot change.

**Resolution ceilings.** Plateaus still cap what a plateau method can score.
`attribution.pointing_ceiling` computes the cap exactly: it enumerates every
set of coarse cells that could be tied at the maximum, using the same
upsampling as the method. Result (ceiling; single-peak-cell value in brackets
where it differs):
| | obvious (mask 27-30) | subtle (mask 23-30) |
|---|---|---|
| CNN Grad-CAM (4x4 map) | 9/16 = 0.5625 | 9/16 = 0.5625 |
| ViT Grad-CAM (8x8 tokens) | 4/9 = 0.444 (0.25) | 1.0 |
| KernelSHAP (4 px cells, both models) | 9/16 = 0.5625 | 1.0 |
On the subtle patch, KernelSHAP is NOT capped: superpixel rows/cols 24-27
lies wholly inside the 23-30 mask. CNN Grad-CAM stays at 9/16, because only
its clamped corner block (28-31) can reach the mask (an interior peak lands
on pixels 19/20). ViT Grad-CAM's corner block is only 2x2 (30-31), so its
obvious-patch cap is lower, not higher. The ceilings are drawn as dashed lines
in `results/figures/detection_pointing.png` and labelled as limits, not
scores. CNN Grad-CAM and KernelSHAP on the obvious patch sit essentially AT
their ceiling at rate 1.0 (0.55-0.56 vs 0.5625). For those two cells,
pointing therefore cannot rank them against pixel methods; AUC and top-k are
the informative metrics there.
Tests: `tests/test_scoring_metrics.py::test_pointing_plateau_straddling_mask_edge`,
`tests/test_attribution.py::test_pointing_ceiling`.

## 9. The attribution cache key now includes the channel-reduction rule (2026-10-13)
`attribution_path` hashes the reduction rule's name and a hash of its
reducer's source (`attribution.reduction_key`). A future edit to a reducer,
or a different `reduction:` setting, therefore gets a fresh cache entry
instead of silently reusing heatmaps made under the old rule. Even a
comment-only edit to a reducer invalidates; that is deliberate.
**The existing heatmap caches predate this key.** They were made by the
then-only rule, abs-sum. Before re-keying them, IG, LRP and Guided Backprop
were recomputed for all four rate-1.0 seed-0 runs (obvious and subtle, both
models): 12 of 12 were bit-identical to the cached files (max relative
difference 0). The 408 existing files (68 valid runs x 6 methods) were then
hard-linked under their new key names; the original files are untouched.
Runs not in that verification slice are trusted on the strength of the code
history (`_reduce` had one rule) plus the spot check, not individually verified.


## 10. Sanity control: clean-trained models on patched images (2026-10-13, 3 seeds)
For each patch type, model and seed 0-2, a model was trained at injection
rate 0.0 (clean CIFAR-10, never sees the patch). All six methods were run on
the SAME 100 patched test airplanes and scored against the SAME masks as the
sweep. Comparison: the rate-1.0 sweep run with the same seed.
**The clean models do not use the patch:** reliance gap -0.005 / +0.007
(obvious CNN / ViT), -0.002 / +0.001 (subtle). Trigger flip rate is
within about 1 point of each model's clean confusion rate (CNN 1.8% vs 1.8%;
ViT 4.8% vs 3.5% obvious, 3.6% vs 3.5% subtle).
Mean pixel AUC, clean model → shortcut model (3 seeds; chance = 0.5):
| method | obvious CNN | obvious ViT | subtle CNN | subtle ViT |
|---|---|---|---|---|
| Integrated Gradients | 0.34 → 0.96 | 0.46 → 0.72 | 0.44 → 0.92 | 0.41 → 0.77 |
| Grad-CAM | 0.34 → 0.99 | 0.46 → 0.72 | 0.45 → 0.86 | **0.61 → 0.55** |
| LRP | **0.77** → 1.00 | 0.41 → 0.59 | 0.44 → 0.91 | 0.45 → 0.71 |
| KernelSHAP | 0.43 → 0.97 | 0.48 → 0.82 | 0.48 → 0.75 | 0.49 → 0.68 |
| Guided Backprop | 0.46 → 1.00 | 0.33 → 0.52 | 0.36 → 0.87 | 0.48 → 0.77 |
| random | 0.51 → 0.51 | 0.51 → 0.51 | 0.50 → 0.50 | 0.50 → 0.50 |
Top-k and pointing tell the same story; full tables with 95% CIs are in
`results/sanity_control.md`.
- **Guided Backprop does NOT score well on the clean model.** This was the
  method most expected to (it is known to behave partly like an edge
  detector, insensitive to the model). Clean-model scores: AUC 0.33-0.48,
  top-k 0.00-0.04, pointing 0.00-0.04, on both patches and both models. Its
  high shortcut-model scores (CNN obvious: AUC 1.00, pointing 1.00) are
  therefore not explained by the patch's visual salience alone.
- **Most methods score BELOW chance on clean models** (AUC 0.33-0.48). A
  clean model's attribution concentrates on the object, and the corner mask
  is mostly background. So the random baseline (0.5) is a lenient floor for
  a corner mask; the clean-model score is the right null. Every sweep score
  should be read as a lift over this null, not over 0.5.
- **Exception 1, LRP on the CNN, obvious patch: clean AUC 0.77 ± 0.14.**
  This is well above chance for a model that does not use the patch: LRP
  responds to the magenta patch's salience. Top-k (0.09) and pointing (0.06)
  stay low, so the effect is a raised rank for the patch region, not a
  peak on it. LRP's shortcut-model AUC of 1.00 contains a salience component
  of about 0.27 above chance.
- **Exception 2, Grad-CAM on the ViT, subtle patch: clean ≥ shortcut on every
  metric** (AUC 0.61 vs 0.55, top-k 0.13 vs 0.09, pointing 0.08 vs 0.07).
  Its above-chance AUC on the subtle patch therefore carries no evidence of
  reliance. The mechanism (e.g. a bottom-right bias of the token map) was not
  investigated.
- **The reliance gate is within the ViT's noise on the obvious patch.**
  Per-seed gaps of the clean obvious ViT: +0.021, +0.057, -0.056 (the
  magenta square occludes corner pixels, which moves a 69%-accuracy model's
  airplane predictions by about ±6 points). One seed exceeds the 0.05 gate
  without any reliance. No sweep decision is affected: every obvious-patch
  ViT sweep run has a gap ≥ 0.41. The subtle clean ViT varies far less (+0.009,
  -0.003, -0.003). The flip rate (primary statistic, #13) does not have this
  problem: clean ViT flip 3.4-6.8% vs sweep ViT 99-100% on the obvious patch.
- Implementation note: with no patched training images, the rate-0 training
  set is the same for both patch types. The obvious and subtle clean
  checkpoints are bit-identical (training is deterministic), so the two
  columns use one network per (model, seed); only the images and masks differ.
Evidence: `results/sanity_control.{md,csv}`, `scripts/sanity_control.py`.

## 11. Method rankings are sensitive to the channel-reduction rule (2026-10-13, one slice)
On rate 1.0, seed 0 (obvious and subtle, both models), IG, LRP and Guided
Backprop were recomputed with `pos` (positive part of the signed RGB sum,
the rule KernelSHAP and Grad-CAM already follow) instead of `abs_sum`. The
sweep was not rerun. Across the 12 (patch type x model x metric) slices:
- The six-method ranking is identical in only 2/12 slices (both are pointing
  on the obvious patch), and the top method is the same in 5/12. Kendall τ:
  median 0.73, minimum 0.20.
- AUC is hit hardest. On the CNN (both patches), the abs_sum ranking puts the
  pixel methods first (obvious: LRP 1.000, GBP 1.000; subtle: IG 0.926). Under
  pos they fall below Grad-CAM and KernelSHAP (obvious GBP 1.000 → 0.625; subtle
  IG 0.926 → 0.671). Mechanism, checked on the CNN rate-1.0 seed-0 runs:
  (a) positive-only maps are exactly 0 on 43-49% of pixels (30-46% inside the
  mask), and that tied block at 0 pulls AUC toward 0.5; (b) for Guided
  Backprop on the obvious (magenta, G = 0) patch, 47% of the in-mask
  |attribution| is in the green channel and all of it is negative ("more
  green, less airplane"). abs_sum counts it; pos discards it. IG has no green
  signal there (input x gradient is 0 where G = 0), so (b) does not apply to IG.
- Pointing is the most stable (τ ≥ 0.60 everywhere; identical on obvious).
  The single strongest pixel usually carries positive evidence.
**Limitation, not a crisis:** the sweep's statements about pixel methods vs
Grad-CAM/KernelSHAP are statements about abs-sum pixel maps. Part of their
AUC / top-k advantage on the CNN comes from counting negative evidence as
salient, which Grad-CAM and KernelSHAP by construction do not. Comparisons
within the pixel methods, and pointing-game comparisons, are less affected.
Single seed, single rate: a sensitivity check, not a re-estimate.
Evidence: `results/reduction_sensitivity.md`, `scripts/reduction_sensitivity.py`.

## 12. Dose-response boundary: the CNN stops using the subtle patch at rate 0.5-0.6; the ViT does not (2026-10-13)
All four runs that failed the reliance gate (gap ≥ 0.05) are **subtle patch,
CNN**: rate 0.6 seed 1 (gap +0.049) and rate 0.5 seeds 0, 1, 2 (+0.022,
+0.035, +0.043). They are kept in `runs.csv` and not scored. The gate is a
threshold on a continuous dose-response curve, and these runs locate where
the CNN's curve crosses it: 2/3 seeds pass at rate 0.6, 0/3 at 0.5. They are
the edge of the CNN's learnable range for a +15 blue shift, not failures.
Trigger flip rate says the same: 2.0-2.6% at these cells, against a clean
confusion rate (unpatched non-airplanes called airplane) of 1.5-1.9%, i.e.
the patch alone flips almost nothing.
**The ViT at the same four cells passes in all of them:** gap +0.260 (0.6/s1)
and +0.223, +0.174, +0.105 (0.5/s0-2); flip rate 18.6%, 16.7%, 11.6%, 6.1%
against its own clean confusion of 2.8-3.0%. Same data, same poisoned subset
(same seed), same patch: the ViT still learns the shortcut where the CNN no
longer does. This is the sharpest single contrast behind #13.
Evidence: `results/runs.csv`, `results/reliance_by_model.md` ("Runs that
failed the reliance gate").

## 13. Reliance claim, restated with flip rate as the primary statistic (2026-10-13)
The reliance gap (airplane accuracy patched − clean) is not normalised for
clean accuracy, and the ViT is the weaker model: its clean airplane accuracy
is lower (e.g. subtle r0.9: 39% vs 69%), so it has more headroom for a large
gap. The comparison in #2 is therefore restated with **trigger flip rate**
(share of patched non-airplanes called airplane) as the primary statistic.
Flip rate does not involve clean-airplane accuracy. The gap is secondary.
Headline counts exclude rate 1.0, where ceilings bind (obvious: both gaps
about 1.0, ViT flip 100%). Paired by seed, tie = |difference| < 0.01:
| | flip rate ViT / CNN / tie | gap ViT / CNN / tie |
|---|---|---|
| obvious, rates 0.5-0.9 (15 pairs) | **15 / 0 / 0** | 15 / 0 / 0 |
| subtle, rates 0.5-0.9 (15 pairs) | **15 / 0 / 0** | 15 / 0 / 0 |
| obvious, rate 1.0 (separate) | 3 / 0 / 0 (ViT at 100% ceiling) | 0 / 0 / 3 (both at ceiling) |
| subtle, rate 1.0 (separate) | 3 / 0 / 0 | 3 / 0 / 0 |
The claim survives the stricter statistic: the ViT flips more patched
non-airplanes than the CNN in all 30 headline pairs. It also survives
subtracting each model's clean confusion rate (ViT about 1 point higher): 30/30, smallest
margin 2.6 points (subtle). Caveat on magnitude: on the obvious patch the ViT's
flip rate is 99-100% at every rate, so there the comparison is ViT-at-ceiling
vs CNN and the size of the difference is bounded by that ceiling.
This supersedes the statistic choice in #2, not its conclusion.
Evidence: `results/reliance_by_model.md`, `src/shortcutbench/report.py`.

## 14. Scoring baseline changed on 2026-10-13; all results from here on use it
For transparency in the write-up: the scoring used for every number in
`results/results.csv`, `summary.csv` and the detection figures changed on
2026-10-13, after the sweep had been run. No model was retrained and no
heatmap recomputed; only the scores were.
- **Pointing game:** all-or-nothing → fractional credit (share of tied-max
  pixels inside the mask). Effect: Grad-CAM and KernelSHAP pointing went up
  (e.g. obvious/CNN 0.000 → 0.398 and 0.541); IG, LRP, Guided Backprop and
  random are unchanged (unique maxima). Full before/after table: #8.
- **Top-k:** the identical `precision` and `recall` columns → one `topk`
  column, plus secondary `precision_k64` / `recall_k64` (#7). Values
  are bit-identical to the old precision column.
- **AUC:** unchanged (bit-identical).
- Per-run score caches carry `SCORING_VERSION` (now 2) in their file name, so
  old scores cannot be mixed in. The pre-change CSVs are not in the repo; the
  differences are fully recorded in #8.
Accepted by the project owner as the new baseline on 2026-10-13.
